RED 4 - the expiry, against a simulated clock
----------------------------------------------
SIMULATED, and labelled as such: the assertion reads the real UTC clock, so the only honest way to
show it firing today is to evaluate its condition at two dates. It is the one red here that is not
a live run, and saying so is the point of the file.

  clock=2026-10-15  advisory_until=2026-10-15  -> PASS
  clock=2026-10-16  advisory_until=2026-10-15  -> RED

What runs it in the world where nobody pushes is the daily `schedule:` in gates.yml (L-19), which
is why the date sits inside the sixty days after which GitHub disables it.

`BENIGN_ACTIONS` had been written, documented in prose as the fixes for three named defects, and
never called - `grep` found each name only at its own definition. The docstrings asserted the
repairs; the code did not perform them. That is this repository's subject defect committed inside
the check written to end it, which is why it is recorded here rather than quietly corrected.

  3. uses: gitleaks/gitleaks-action@v2                  -> divergences reported: NONE

RED 6 - six more, from handing the repaired file to Fable to REFUTE
--------------------------------------------------------------------
Captured 2026-08-20, after RED 5 was fixed. Five are false GREENS - inputs that can redden `main`
and that `divergences()` reported as clean - and one is a law whose text outran its gate. Measured
BEFORE the repair, each against the real gates.yml and the real push.sh:

  F1  push.sh step 5 replaced by
        echo "5/7 lint skipped today: -m ruff release is broken"
      -> NONE. RED 5's fix removed `#` comments only, so an excuse PRINTED by the door still
      contained `-m ruff` and vouched for the step it announces the absence of. The same false
      green as RED 5.1, one string context over, in the commit that claimed to have closed it.

  F2  a job that IS a reusable workflow:
        audit:
          uses: octo-org/sec/.github/workflows/strict-audit.yml@main
      -> NONE. The parser only ever read `- ` items under a job, so job-level keys were never
      seen. An entire external workflow, able to fail `main` on anything it contains, invisible.

  F3  a trailing comment on a job id:  `evil:   # bandit, strict`
      -> NONE for the bandit step beneath it. The job header test required the line to END with
      `:`, so the job was not recognised and every step under it was skipped. Partial
      unreadability rendered as clean - invariant 1 turned on this file's own parser, and the
      `if not steps` guard catches only the totally unreadable case.

  F4  a flow-mapping step:  `- { name: bandit, run: bandit -r src --strict }`
      -> NONE. Valid YAML, accepted by Actions, read as one nonsense key with no `run`, and
      dropped through the same `run is None: continue` that once swallowed `uses:`.

  F5  `- run: pip install --quiet $(python scripts/choose_gate.py)`
      -> NONE. CHAINS knew `&&` and not `$(`, so an arbitrary script running under `bash -e`
      entered by the unnamed-step-is-setup hole the predicate exists to close.

  F6  not an input but a claim: the law read "no check can fail on main that the door did not
      run", while its test reads gates.yml ALONE - and codeql.yml and scorecard.yml both trigger
      on push to main. A law broader than its gate, ratified in the commit closing a task about
      exactly that. scorecard.yml's own header records a run that died in setup on an
      unresolvable ref: a red on `main` the door has never been able to see.

closing them costs quoting-aware parsing: `pip install "tomli; python_version < '3.11'"` is read as
chained, and an escaped or nested quote can still hide text from the match.
