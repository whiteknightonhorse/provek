WHY THIS FILE EXISTS. Invariant 5: a test must be ABLE to fail, and the red run is the only proof
of it. "The section exists" is not a test.

TWO BREAKS, NEITHER A STRAWMAN. The first is the behaviour the Amadeus SDK itself ships; the
second is a defect this repository actually committed and Fable caught before the push.

  BREAK 1 - `classify_reading` in src/amadeus/demo_audit.py, cut short with:

      found = _dig(reading.get("body"), SHAPE[endpoint])
      return Reading(endpoint, ReadingState.MEASURED, Measurement(value=found or 0),
                     "answered with HTTP 200")

  Trust the status code, and let a missing height fall back to a number. `ChainAPI.getTip()` is
  `return this.client.get('/api/chain/tip')` and no schema is applied to a success body, so a 200
  carrying another portal's JSON reaches the caller as the chain tip. `or 0` is the second half:
  the absence becomes a zero, which is invariant 1.

  BREAK 2 - the control gate in `judge()`, deleted:

      if sdk_finding is SdkFinding.CONTROL_DID_NOT_RUN:
          verdict = DemoVerdict.NOT_DEMONSTRATED

  Verbatim the state the demo was in when it was first handed to Fable: a run whose instrument
  control could not be set up still returned `demonstrated` and exit 0, carrying the README's
  headline finding while having established nothing. `check_did_not_run` wearing a pass.

WHAT THE RED RUN SHOWS. The shape tests fall, and so do the two that guard the verdict - the
foreign-document run and the un-run control. A reader can check that the failures name the
behaviours the demo argues for, rather than merely that something went red.
