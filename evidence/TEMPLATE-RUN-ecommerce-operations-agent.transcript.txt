A REAL DEFECT WAS FOUND AND FIXED, NOT PAPERED OVER
====================================================================================================
The first version of apply.py's recheck_bounds() took `max_pct=MAX_PRICE_MOVE_PCT` as a default
parameter, which Python binds once at function-definition time. SKILL.md's own Security section
requires the bounds check to run "again at apply time against the live configuration, not only
against the configuration in force when the proposal was staged" - test 3 exercises exactly this
by lowering the configured bound between staging and apply, and the stale default parameter meant
the lowered bound was never actually consulted, so a proposal that should have been refused was
applied. Fix: recheck_bounds() now reads `config.MAX_PRICE_MOVE_PCT` from the module at call time
instead of capturing it as a default argument. Same class of defect as the lead-generation-agent
dry run's stale-path bug: a value captured once at definition/import time instead of read fresh
when it is used - caught here because the template's own Tests section specifically demands the
recheck-at-apply-time behavior, which is exactly what a witnessed dry run is supposed to catch.
