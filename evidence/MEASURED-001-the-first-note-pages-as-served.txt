MEASURED-001 - the first method note pages, read from the live origin
==================================================================================================

T-C4's acceptance is about what provek.dev SERVES, so every reading below was taken over the
network against https://provek.dev. Nothing here is a report by a tool about itself, and nothing
here is a reading of `web/dist` (L-3, and the project rule that the artefact under test is the one
that was submitted).

Two instruments, both named with their versions, and both able to refuse:

    W3C Nu validator   https://validator.w3.org/nu/?doc=<url>&out=json
    Lighthouse 12.8.2  local, driving Chromium 151.0.7922.108 (snap), headless
                       CHROME_PATH=/usr/bin/chromium-browser lighthouse <url> --quiet --output=json

WHY LIGHTHOUSE IS LOCAL AND NOT THE PAGESPEED API. The task proposed the anonymous PageSpeed
Insights API on the assumption that a local Chrome would not fit this host. Both halves are wrong
and both were measured rather than argued. The anonymous API is not throttled, it is QUOTA-ZERO: it
answers HTTP 429 with `quota_limit_value: "0"`, measured 2026-08-21 for provek.dev and for
example.com alike, so it is structural and not a used-up daily allowance. No Google API key exists
on this host. A 429 is an instrument refusing to answer and is never a score. The local CLI does
fit, and the reason to distrust it is different and is dealt with below.

2. LIGHTHOUSE
--------------------------------------------------------------------------------------------------

BENCHMARKINDEX IS RECORDED BESIDE EVERY SCORE, and it is the reason the first two readings are
published here rather than discarded. Lighthouse reports the CPU it actually got; D-14 recorded
100/100/100/100 at benchmarkIndex 2916, and a run taken on 2026-08-21 while the note generator was
burning the core measured 2088 and reported Performance 84. A score is only a fact about the site
once the machine that took it has been ruled out as its cause, so a contended run is not the site's
score and is never reported as one.

    time (UTC)  page                                    bi     perf a11y bp  seo   CLS      TBT
    02:30:13    /method/notes/not-measured-is-not-zero/ 2096.5  83  100  100 100  0.2524   158
    02:32:04    /method/notes/not-measured-is-not-zero/ 2133.0  83  100  100 100  0.2524   150
    02:32:35    /  (CONTROL)                            2197.5  95  100  100 100  0.0608   147

The first run was taken while another tenant's ffmpeg was using 349% CPU; this project yields on
contention, so it was re-run at 02:32 on a settled host and read 83 again. Two runs agreeing is not
by itself evidence about the site, so the LANDING was measured as a control in the same minute: 95
at a marginally HIGHER benchmarkIndex than the note's 83, with total blocking time 147ms against
150ms. Same host, same minute, same CPU - which is what rules the machine out and makes the twelve
points a property of the document.

The whole of the difference was cumulative layout shift, 0.2524 against 0.0608, in a single event
moving all of `<main>`. Lighthouse names the cause: three woff2 faces, "Web font loaded". The site
ships `font-display: swap` with the faces referenced from inside the stylesheet, so they cannot be
discovered until the CSS is parsed; text paints in the fallback and reflows. The cost is
proportional to how much text a page has, and this note is a 5404px column of prose - the first
page on this site with enough text for it to matter. Fixed by preloading the three faces in
`web/prerender.mjs`.

Read after the fix, on deployment 2c06d10:

    time (UTC)  page                                    bi     perf a11y bp  seo   CLS      TBT
    02:36:16    /method/notes/not-measured-is-not-zero/ 2169.5  98  100  100 100  0.0000   163
    02:36:29    /method/notes/                          2143.5  98  100  100 100  0.0000   160
    02:36:41    /  (CONTROL)                            2160.0  99  100  100 100  0.0000   101

Every category on both note pages is at or above 95, which is T-C4's criterion. The control moved
too - the landing went from 95 to 99 and its own CLS from 0.0608 to zero - which is the reading
that confirms the diagnosis was the site's font strategy rather than something about the note: a
fix aimed at one page could not have improved a page it does not touch.

WHAT IS NOT ESTABLISHED HERE. That these scores hold on a visitor's machine, on a cold cache from
another continent, or on mobile hardware. Lighthouse's own throttling stands between this reading
and any of those, and the benchmarkIndex column exists precisely because this host is not a
reference machine - every number above was taken at roughly 2100-2200 where D-14 measured 2916, so
this host is about a quarter slower than it was four days ago and the readings are conservative
rather than flattering. What is established is a comparison between pages taken minutes apart under
the same conditions, and the fact that the shift a reader would have seen is gone.
