RED-021 - a deploy gate that reads less every release
==================================================================================================

Regenerate with:  python3 evidence/RED-021-generator.py
Verify with:      python3 evidence/RED-021-generator.py --check

SUBJECT: tests/test_verify_live_reads_the_function.py
         scripts/verify_live.sh

T-C4 published the first method note and added its two routes to the live check. The
suite went red on the addition, because the address list existed twice - once in the
script and once as a hand-written HEALTHY fixture beside the tests - and nothing had ever
compared them. The repair was not to patch the literal (L-20: the finding in a divergence
between two copies is the absence of the comparison, not the value that differed) but to
read the fixture out of the script, so there is one list.

That repair introduces its own hole, and half of this file is about it. A derived fixture
SHRINKS WITH ITS SOURCE: an address deleted from the script disappears from the fixture
too, and every assertion here keeps passing over a deploy check that reads less of the
site than it used to. So a floor sits under the derived list, asserting that the
load-bearing addresses are still in it, and pinning the CODE as well as the path.

THE FOUR MUTATIONS BELOW ARE OF TWO CLASSES, AND THE DISTINCTION IS LOAD-BEARING:

  [refused-to-build]  the parser cannot read the list, so the fixture refuses to exist
                      and pytest exits 2 with a collection error. This is NOT a failing
                      assertion and is not filed as one - a suite that never ran and a
                      suite that ran and failed are two states of the world. Each is
                      required to print its own refusal message verbatim; a collection
                      error saying anything else is an ordinary crash and is refused.

  [assertion-red]     the suite runs, drives the script against a stub origin, and one
                      named test fails (pytest exit 1). The instrument control
                      test_the_probe_never_writes must SURVIVE each of these, because it
                      can only pass if the script was really executed - a red produced by
                      a suite that stopped running proves nothing (L-28).

Every mutation was applied to a clean tree, run alone, and restored byte for byte before
the next. The four failure sets are DISTINCT, which the generator checks rather than
asserts: identical output from different mutations is how RED-013 shipped a transcript
belonging to a different run.
